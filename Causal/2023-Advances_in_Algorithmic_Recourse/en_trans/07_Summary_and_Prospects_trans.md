# 总结与展望（Summary and Prospects）

## 7.1 展望（Prospects）

在前几节中，我们介绍了旨在提供**算法追索（algorithmic recourse）**的现有工作的定义、公式化和解决方案。我们表明，生成追索解释和建议需要基于不同层次的因果知识进行**反事实推理（counterfactual reasoning）**。反事实推理不仅根植于科学哲学（Lip90; HS86; Hil90; Lew73; Lew86; Woo05），也根植于人类主体的心理学（Mil18; Mil19; Byr19），并受益于坚实的技术基础（HP05; Bar+20）。用户研究表明，因果关系是通过评估反事实来评估的（MK93），并且反事实模拟被用于预测未来事件（Ger+17）。特别是在**可解释人工智能（Explainable Artificial Intelligence, XAI）**的背景下，已有研究表明，反事实可以“使不可理解的系统的决策对开发者和用户变得可理解”（Byr19），并且当呈现反事实实例时，人们在预测模型行为方面表现更好（Lag+19）。组织寻求部署基于反事实的解释，理由是它们易于理解（Bha+20b; Bha+20a）且符合**通用数据保护条例（General Data Protection Regulation, GDPR）**（WMR17）。最后，从实践者的角度来看，算法追索不仅受益于广泛实践的开源实现共享（见表1.1），还开发了各种图形界面以帮助非技术利益相关者上手（Wex+19; CMQ20; Gom+20）。

然而，现有设置中存在许多隐含假设，例如，世界动态是已知且不变的，预测（监督）模型是固定的，并且变化仅由寻求追索的个体的行动引起。此外，在所考虑的多智能体设置中（例如，银行和贷款申请人），假设智能体诚实行事，不存在博弈或虚假特征报告，并且智能体在最小化商定的目标函数方面目标一致。下面，我们探讨这些假设不成立的设置，并提供扩展到更现实的追索设置的潜在解决方案。

## 7.1.1 超越确定性追索（Beyond deterministic recourse）

在（1.2）中，我们看到，在反事实实例 $\mathbf { x } ^ { \mathsf { C F } }$ 被分配为在假设行动 a 下 $\mathbf { x } ^ { \mathsf { F } }$ 的结构反事实的约束下，即 ${ \pmb x } ^ { \mathsf { C F } } = { \pmb x } ^ { \mathsf { S C F } } ( { \pmb a } ; { \pmb x } ^ { \mathsf { F } } ) \ ( \mathsf { K S V } 2 { \tau } )$ ，生成了最小后果性建议。然而，精确计算结构反事实依赖于强假设（即，真实的**结构因果模型（Structural Causal Model, SCM）**是一个加性噪声模型并且是已知的）。早些时候（Kar+20b），我们表明，在没有对真实 SCM 的完整知识的情况下，无法精确进行反事实分析，因此无法确定性地提供追索。尽管所提出的方法以高概率提供追索，但它们是在指定因果充分图的前提下进行的。该方向的未来研究可能会探索限制较少的设置，或许考虑隐藏的混杂因素（Küg+21），或部分观测图（AIR96; TP01; CY99），从而进一步增加追索建议的不确定性（Bec22; KFGW21）。或者，随机性的来源可能通过非确定性的决策系统进入追索过程。例如，已经证明，对于在选择性标签上训练的模型，公平和最优的决策应该是随机做出的（Kil+20; Bec+19; TGR20）。

## 7.1.2 超越监督追索（Beyond supervised recourse）

在第1.3.2节中，我们讨论了如何将标准的二分类设置扩展到支持多分类和回归。除了这些经典的监督学习设置之外，个体可能受制于一个自动决策者，该决策者决定跨群体的申请者与资源的匹配，例如，儿童的幼儿园分配、低收入家庭的住房分配。或者，可以预期在更具交互性的设置中生成解释，例如，针对**强化学习（reinforcement learning）**智能体的行动和策略（Mad+20; Waa+18; Mad+19; Ros+20）或针对推荐系统（Gha+20; DRR20）。最后，也可以为时间序列数据生成解释（APMRRÁ20; Ate+20; LHR20），这可以扩展到支持在线数据流和随时间变化的模型（PBK20; BSR20; VA20; DGK21; Roj+21）。

## 7.1.3 超越个体化追索（Beyond individualized recourse）

到目前为止，所提出的公式旨在提供与单个个体相关的追索解释，并假设追索建议将由该个体执行。然而，将追索的概念扩展到所涉及的数据主体之外，或群体中的单个个体之外，是自然而然的。

前一种设置的一个例子是，当患者因丧失行为能力而无法直接行使其代理权时，其家庭成员代表他们决定治疗方案（VA20）。人们还可以考虑司法过程中的常见情况，即法律顾问代表其客户寻求追索，然后由另一位受托人执行。在这种情况下，行动的成本和可行性的公式可能需要调整，以考虑主体和行动者双方的限制。

或者，追索可以通过一群人的集体行动来实现，而不是单个个体的行动（KSV21）。例如，社会和政治活动家的努力可能最终导致法律变革，从而为一群个体提供更好的条件。在这种情况下，在个体层面上不可操作（或成本高昂）的（背景）变量可能在群体层面上变得可操作，这反过来可能降低群体所有成员的成本。这个例子也表明，背景变量可能捕获并非个体特征但会影响个体的上下文信息（例如，经济状况）。此外，个体可能无法控制这些随时间变化并违反世界平稳性假设的宏观变量。另外，明确考虑多个智能体（OK21），为每个智能体构建心智理论以便最佳地说服（KR21），以及将追索视为在已采取行动的非即时效应下的序贯博弈（VHD21; NN21），是未来研究中一个尚未充分探索的领域。最后，由于假设的不确定性（Kar+20b）或作为对系统其他属性（例如，公平性（Kar+20a; Gup+19; USL19; CMQ20; RL20），我们将在下面进一步探讨）的有意研究，可能在子群体层面上分析追索的需求会出现。

## 7.1.4 论追索与伦理机器学习的相互作用（On the interplay of recourse and ethical ML）

上述研究问题主要集中在一种利益相关者：受影响的个体。然而，赋予个体追索权不应在真空中考虑，也不应独立于提供解释/建议可能对其他利益相关者（例如，模型部署者和监管者）产生的影响，或与其他期望的属性（例如，公平性（第5章）、鲁棒性（第6章）、安全性、隐私性）的关系，这些统称为**伦理机器学习（ethical ML）**。我们在下面探讨这种相互作用。

### 7.1.4.1 追索、安全性与隐私（Recourse, security, and privacy）

在机器学习API的各种设置中，已经提出了模型提取的担忧（Tra+16; LM05; WG18; RST19）。在这种情况下，对手旨在获得一个与目标模型 h 相似（例如，在保真度方面）的代理模型 $\hat { h }$：

$$
h \approx \hat {h} = \arg \min _ {\hat {h} \in \mathcal {H}} \mathbb {E} _ {\mathbf {x} \sim P (\mathbf {x})} \left[ \mathcal {L} (h (\mathbf {x}), \hat {h} (\mathbf {x})) \right]. \tag {7.1}
$$

这里，对手可能在不同查询预算（无限制、速率限制等（Ily+18; Che+20））下访问各种模型输出（例如，分类标签（LM05）、类别概率（Tra+16）等）。在存在额外信息（例如输出相对于输入的梯度1（Mil+19b）或对比解释（ABG20））的情况下，模型提取可能会加速。与追索相关且具有实际意义（USL19; SF19; SB18; BSR20）的是，研究能够访问追索API的对手提取模型的能力。具体来说，我们考虑这样一个设置：对手可以访问预测API和追索API，该追索API给定一个事实实例 $\mathbf { x } ^ { \mathsf { F } }$ ，使用已知的距离函数 $\Delta : \mathcal { X } \times \mathcal { X } \to \mathbb { R } _ { + } . ^ { 2 }$ 返回一个最近的对比解释 $\mathbf { x } ^ { \mathrm { * C F } }$ 。需要对这些API进行多少次查询才能对 h( ) 进行功能等效的提取？

在第一种攻击策略中，人们可以在一个数据集上学习代理模型，该数据集中的事实实例和标签（来自训练集或随机采样）被反事实实例和反事实标签所增强。

这个想法由（ABG20）探索，他们证明即使在低查询预算下，也可以提取高保真度的代理模型。虽然易于理解和实现，但这种攻击策略隐含地假设构建的数据集具有独立同分布（i.i.d.）数据，因此没有利用事实对和反事实对之间的关系。

另一种攻击策略考虑模型 h 可以完全由其决策边界或互补的决策区域 $\{ \mathcal { R } _ { 1 } , \cdots , \mathcal { R } _ { l } \}$ 表示。从追索API返回的每个对比解释告诉我们，围绕事实实例的所有实例，直到距离 $\Delta ( \mathbf { x } ^ { \mathsf { F } } , \mathbf { x } ^ { \mathsf { * C F } } )$ ，根据 h 与 $\mathbf { x } ^ { \mathsf { F } }$ 共享相同的类别标签（否则该实例将成为最近的对比解释）。更正式地说，$h ( \mathbf { x } ^ { \mathsf { F } } ) = h ( \mathbf { x } ) \forall \mathbf { x } \in B _ { \mathbf { x } ^ { \mathsf { F } } } ^ { \Delta }$ ，其中 $B _ { { \nu } ^ { \mathsf { F } } } ^ { \Delta }$ 被称为 ∆-事实球，以 $\mathbf { x } ^ { \mathsf { F } }$ 为中心，半径为 $\Delta ( \mathbf { x } ^ { \mathsf { F } } , \mathbf { x } ^ { \ast \mathsf { C } } )$ 。因此，模型提取问题可以表述为填充所有决策区域所需的事实球的最大数量（见图7.1）：

$$
\operatorname * {P r} \left[ \operatorname{Vol} \left(\mathcal {R} _ {l}\right) - \cup_ {i = 1, \mathcal {B} _ {\mathbf {x} ^ {\mathrm{F}} i} ^ {\Delta} \subseteq \mathcal {R} _ {l}} ^ {n} \operatorname{Vol} \left(\mathcal {B} _ {\mathbf {x} ^ {\mathrm{F}} i} ^ {\Delta}\right) \leq \epsilon \right] \geq 1 - \delta \quad \forall l \tag {7.2}
$$

与其他提取设置一样，$\hat { h }$ 随后可用于推断训练集中个体的私人信息，发现可利用的系统漏洞，或用于免费的内部使用。理解攻击策略可能会指导追索政策和防御机制的设计，以阻碍此类漏洞的利用。

令人惊讶的是，模型不必以上述意义被提取才能泄露敏感信息。基于上述直觉，我们注意到，单个对比解释告知数据主体，在某个邻域 $( \mathrm { i . e . } ,$ ，在 $B _ { { \bf x } ^ { \sf F } } ^ { \Delta }$ 内）中没有实例的预测是不同的。此信息告知数据主体，例如，他们相似的朋友是否也被拒绝了贷款，从而侵犯了他们的**预测隐私（predictive privacy）**。即使部分了解朋友的属性，对手也可能利用关于 $B _ { { \bf x } ^ { \sf F } } ^ { \Delta }$ 中共享预测的信息来执行**成员推理攻击（membership inference attacks）**（SSZ19）或推断缺失的属性（DF18）。当生成多个多样化的解释时，这个问题会变得更糟，并且是一个悬而未决的问题。

### 7.1.4.2 追索与操纵（Recourse and manipulation）

尽管追索的一个核心目标是培养个体与自动化系统之间的信任，但假设所有各方在此过程中都诚实行事是过于简单的。例如，在了解了决策过程的一些信息（也许是通过给予相似个体的建议）后，个体可能会夸大他们的一些属性，以获得更有利待遇的机会（VA20）。提供追索的一方也可能违反信任。如前所述，追索解释/建议的多样性（见§1.4.1.1）可能允许组织挑选“从许多同样合理的解释中最能被社会接受的一个”（HL20; LB20; BSR20）（另见，**公平洗白（fairwashing）**（Aïv+19））。在这种激励不匹配的情况下，监管机构的监督（或许是对任何一方进行随机审计）似乎是必要的。另一种解决方案可能涉及强制要求最低数量的多样化追索产品，但这将与安全考虑相冲突。

## 7.1.5 迈向统一基准（Towards unifying benchmarks）

表1.1概述了寻求追索的各种设置。尽管基于稳健工具的开源实现丰富，并且在各自的设置中运行良好，但缺乏追索的比较基准。对于后果性建议而言，这个问题更加严重，因为这些建议进一步依赖于关于因果生成过程的假设。然而，为了取得客观的进展，新的贡献应该与现有方法进行评估。因此，社区的下一步是策划一个在线挑战（例如，使用Kaggle）来基准测试现有和新方法的性能。为了广泛覆盖实际设置，我们设想多个赛道，作者可以在其中提交他们在给定固定分类器、测试数据集和预定义距离/成本定义下生成的解释/建议，并使用§1.4.1中定义的指标进行评估。作者还可以提交满足额外可操作性、合理性和多样性约束的结果，并以此进行比较3。最后，除了努力为追索建立包罗万象的评估基准之外，推动理解追索方法与其他可解释性方法之间的关系也是非常受欢迎的。我们特别参考（KM+21; Eck+21; FPH20; GPS21）等近期工作，这些工作展示了追索如何导致或源于诸如归因方法之类的其他方法。鉴于该领域的后果性性质，对追索进行用户测试比针对非后果性领域中其他利益相关者的可解释性方法更困难（如果在伦理上可能的话）。尽管如此，鉴于最终目标不仅是构建解释，而是构建可靠和稳健的解释，未来的研究应探索对此类不确定性进行建模的方法。

3自稿件首次在线发布以来，已有若干工作朝这个方向推进，包括（Zho+21; OM21; Ram+21; OM21; HIA21），以及一个用于以统一和可比较的方式运行多种追索生成方法的公共仓库（Paw+21b）。

这不仅对追索建议的接收者很重要，对提供此类建议的机构也很重要，因为从某种意义上说，这是在满足某些条件时提供某种资源的双方之间的具有约束力的合同。

## 7.2 结论（Conclusions）

我们的工作从一个案例研究开始，讲述了一位28岁的女性专业人士被自动化决策系统拒绝贷款。我们旨在帮助这个个体克服她的困境，即实现**算法追索（algorithmic recourse）**，这取决于对两个问题的回答：为什么（why）？以及如何（how）？我们研究了这些问题之间的关系，并得出了不同的回答，即，**对比解释（contrastive explanations）**和**后果性建议（consequential recommendations）**。考虑到追索的目标，我们强调最小后果性建议优于最近对比解释，因为前者直接优化了个体的最小努力。此外，我们注意到，提供追索建议自动意味着追索解释（通过模拟所采取行动的因果效应），而反之则不然。然而，在回顾文献时，我们观察到对后果性建议的探索不足，我们将其归因于它依赖于在行动发生的世界的因果生成过程层面上的额外假设。

我们指出，追索的主要重点是为克服不利预测提供可操作的建议，这与突出具有不同预测的相似实例的**反事实解释（counterfactual explanations）**不同。这种细微差别在关于**对抗性机器学习（adversarial machine learning）**的并行文献中也很明显（见§1.3.6）：反事实解释识别对抗性实例，而追索则告知如何创建它们。因此，为了在现实世界约束下提供可操作的建议，我们必须考虑对一组变量的操作可能会对其他变量产生后果。这些约束可以使用SCM框架来解释，因此，在我们的工作中，我们主要采用这种方法。

除了统一和精确定义追索之外，我们还概述了对现实追索设置进行建模所需的许多约束（例如，可操作性、合理性、多样性、稀疏性）。通过附带的说明性示例，我们区分了距离与成本、合理性与可操作性（可行性）等概念，这些概念的区别在文献中很大程度上被忽略了。自始至终，我们重申这些概念是个体/上下文相关的，并且公式化不能仅从技术角度出发。我们在表1.1中总结了技术文献，作为寻求满足特定属性方法的实践者的指南，以及希望识别未解决问题和有待进一步开发方法的研究者的指南。

最后，我们确定了一些前瞻性的研究方向，这些方向挑战了现有设置的假设，并提出了扩展，以更好地将追索置于更广泛的伦理机器学习文献中。所呈现的示例和讨论旨在说明利益相关者需求的多样性，以及我们寻求与追索一同提供的理想系统属性（公平性、安全性、隐私性、鲁棒性）之间的紧张关系。令人满意地解决这些需求并应对由此产生的权衡可能需要新的定义和技术，并依赖于技术和社会科学专家小组的跨学科专业知识。我们希望本文档能够指导这一方向的进一步讨论和进展。
